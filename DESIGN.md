# DESIGN — Ryzon Automation website funnel

> `/impeccable document` was not available in this environment. This file is written by hand to cover what it would produce: the design system as built, and the rules that keep new work consistent with it. Product facts, audience and voice live in `PRODUCT.md`.

## 1. What the design has to do

One page, one action. Every screen should move a busy, phone-first small-business owner toward **requesting the free demo** (`/#demo`), with the offer always visible: **$40/mo · $0 design fee · free demo**. The design earns trust by being plain, fast and honest: there are no fake badges, timers or stats, and unverified proof shows as a labeled placeholder rather than an invented one.

Principles, in priority order:
1. **The offer is never more than a glance away.** Hero, offer stack, pricing, the risk-reversal band, the mobile CTA bar and every section CTA repeat it.
2. **Show, don't claim.** Example designs and a live style switcher let people see the work.
3. **Calm and legible over clever.** Big type, strong contrast, generous targets, nothing below 16px.
4. **One system, seven skins.** Every visual value is a token. Changing `<html data-theme>` restyles everything.

## 2. Tokens

`tailwind.config.ts` **replaces** Tailwind's theme instead of extending it. Default colors, spacing, type, radii and shadows do not exist, so off-system values can't creep in. Every themeable value is a CSS variable set per style in `app/styles/themes.css`. That file is generated by `scripts/themes.mjs`; edit the script, never the CSS.

### Color roles
| Token | Use |
|---|---|
| `canvas` | Page background |
| `surface` | Cards, forms, inputs |
| `ink` | Text, borders, hard shadows |
| `muted` | Secondary text (passes 4.5:1 on canvas and surface) |
| `rule` / `grid` | Hairlines, the blueprint grid backdrop |
| `accent` | Links on hover, focus ring, selection, badges |
| `cta` / `on-cta` | The primary action only. One per view where possible |
| `band` / `on-band` | Inverted full-width bands (risk reversal, footer) |
| `on-ink`, `on-accent` | Text on filled ink or accent |
| `danger` | Errors only |

Never use raw hex in components. If a role is missing, add it to every theme in `scripts/themes.mjs`.

### Type
- Two families per theme: `font-display` (headlines; UI too unless the theme sets `--font-ui`) and `font-body`. All are loaded with `next/font` (`display: swap`, self-hosted). Only the default theme's two faces preload; the others load when a visitor picks that style.
- Scale (`text-*`): sm 16 · base 17 · lg 19 · xl 24 · 2xl 30 · 3xl 38 · 4xl 48 · 5xl 60 · 6xl 76 · 7xl 96 px. **Nothing smaller than 16px**, including legal text and labels.
- Weights are tokens: `font-normal`, `font-bold` and `font-heavy` resolve per theme.
- `.display-tight` applies the theme's headline variation (for example Martian Mono's width axis). `.display-ui` applies the UI variation and swaps in `--font-ui`.
- `h1`–`h3` use `text-wrap: balance`, and long copy uses `.text-pretty`. Lining numerals everywhere, plus `tabular-nums` in tables and counts.

### Space, shape, depth, motion
- Spacing is a fixed 4px-based scale (0.5 → 80). Max widths: `page` 75rem, `wide` 48rem, `measure` 38rem (body copy).
- Radius: `rounded-ui` (controls) and `rounded-card` (cards), set per theme: 0 for brutalist, editorial and luxury; a pill for minimal, organic and playful.
- Borders: `border` (hair), `border-2` (strong), `border-3` (heavy), with widths set per theme.
- Shadows: `shadow-hard` / `shadow-hard-lg`. These are offset block shadows in brutalist and playful, soft in minimal, organic and corporate, and none in editorial and luxury.
- Motion: `duration-fast` 150ms, `duration-base` 220ms, `duration-slow` 480ms; easing `ease-out`. Buttons "lift" by `lift-x`/`lift-y` on hover. Only `transform`, `opacity`, `color`, `background-color` and `box-shadow` animate; never `transition: all`. `prefers-reduced-motion` drops every animation and transition to near zero and turns off smooth scrolling.

### Breakpoints
`xs` 375 · `sm` 480 · `md` 768 · `lg` 1024 · `xl` 1280 · `2xl` 1536. Design mobile first. No page may scroll sideways at 320px or wider.

`short:` is a custom variant for screens 500px tall or less, which mostly means phones in landscape. Use it to tighten bars and menus, not to hide content.

## 3. The seven styles

| id | Name | Display / body | Canvas · ink | Accent | CTA | Shape |
|---|---|---|---|---|---|---|
| `brutalist` (default) | Technical brutalist | Martian Mono / Archivo | #E4E5E0 · #000 | #1A33E8 blueprint | #FF4F00 signal | Square, 4/8px hard shadows, grid backdrop |
| `minimal` | Modern minimal | Instrument Sans | #FAFAF8 · #18181A | #2F49C9 | #0B6E4F | Pill controls, 16px cards, soft shadow |
| `editorial` | Bold editorial | Bodoni Moda / Libre Franklin | #FFF · #0A0A0A | ink | #D7141A | Square, no shadow, rules |
| `organic` | Warm organic | Fraunces / Karla | #F3EDE2 · #2A251E | #4E6B35 | #B4441F | Pill, 28px cards, soft shadow |
| `corporate` | Corporate clean | Public Sans | #F4F6F9 · #0E1B2C | #1F4FBF | #12805C | 6/10px radius, light shadow |
| `luxury` | Luxury dark | Cormorant Garamond / Jost | #0E0D0B · #EEE7D8 | #A9B7C2 | #CDAA5E | Square, no shadow, `color-scheme: dark` |
| `playful` | Playful | Bricolage Grotesque / Nunito | #FFF3D6 · #1E1446 | #2B54E0 | #FF3B7A | Pill, 24px cards, ink block shadow |

How styles are applied:
- The switcher (`#styles`) sets `data-theme` on `<html>`, saves it in `localStorage`, and mirrors it to `?style=` so a look can be shared.
- An inline head script (`themeBootScript`) applies the saved or linked style before first paint.
- The chosen style pre-fills "Style you like" in the demo form.
- Preview cards in the switcher only get their `data-theme` once the section is near the viewport, which keeps the first paint light.

Every style must pass WCAG AA contrast for text, hover and disabled states. `a11y.mjs` checks this in all seven.

## 4. Components

| Component | Where | Notes |
|---|---|---|
| `CtaButton` | Section CTAs | Primary = `cta` fill + hard shadow + lift. Labels are offer-led, Title Case: "Get My Free Demo", "See My Free Design", "Start My Free Demo" |
| `OfferLine` | Hero, offer, demo | The three-part offer, always as real text |
| `Heading` | Every section | One `h1` per page. `h2` per section, `h3` inside. Never skip levels |
| `Section` / `Container` | Layout | `Section` provides the anchor id, labelled-by heading, and vertical rhythm |
| `Field` | Forms | Label above, control, then hint or error. Errors are linked by `aria-describedby`, get `aria-invalid`, and the first invalid field gets focus on submit |
| `Placeholder` | Images not yet supplied | Typed slot with the image prompt and a visible label. Fixed aspect ratio, so it never shifts layout |
| `Wordmark` | Headers | Text logo until a file is supplied. Its accessible name always contains the visible text |
| `MobileCtaBar` | Phones (below md) | Fixed bottom demo CTA. It stays hidden until the hero CTA (`[data-cta-bar-after]`) scrolls off the top, so a phone never shows two CTAs at once. On legal pages it waits for the title instead. It slides away and goes `inert` while a form section (`[data-hide-cta-bar]`) is on screen. Safe-area padded, and compact in `short:` |
| `SiteHeader` + `HeaderAutoHide` | Every site page | Sticky. 56px on phones, 64px from md. On phones and short screens it slides away while you scroll down and returns on a real scroll up (touch, wheel or keys; layout shifts don't count), on focus, or near the top. Below md the header drops its CTA because the hero and the bottom bar carry it |
| `Message` | Flow pages | Full-page card for confirmations, expired links and thank-yous. Defaults to call and email actions |
| Admin `Button`, `Panel`, `Notice`, `StatusBadge` | `/admin` | Same tokens. `Notice` announces results (`role=status` or `alert`) |

## 5. Patterns

- **CTAs.** Every demo CTA on every page links to `/#demo`. Section CTAs are links (`<a>`), actions are `<button>`, and nothing clickable is a `div`.
- **Forms.** Every control has an `id`, `name`, `autocomplete` and a visible label. Email fields turn off spellcheck and autocapitalize. Placeholders show an example and end with "…".
  - Validation runs on blur and on submit, never mid-typing. Errors say how to fix the problem.
  - Leaving the page with typed, unsent input asks first.
  - The demo form is two steps (name and email, then business details) to lower the first commitment.
  - With JavaScript off, both steps show and the form posts to `/api/lead`, which redirects to `/thank-you`.
- **Phones.**
  - Fixed bars never stack at the top of a page: the header shows, and the bar waits.
  - While reading, only the bar is visible (66px; 62px in landscape).
  - At 320×568 the headline, the offer line and the hero CTA all fit on the first screen.
  - The menu drawer fits short landscape screens in two columns.
  - Example cards turn sideways (image left) under 375px.
  - The recommended plan comes first on /go-live.
  - The admin table becomes cards, and its filters fold behind a button.
- **Touch.**
  - `hover:` styles only apply on devices that can hover (`hoverOnlyWhenSupported`, and `@media (hover: hover)` in the per-style CSS), so a tap never leaves a stuck hover state.
  - Buttons get `active:` press states instead, and links, menu rows and FAQ rows dim while pressed.
  - Every control is at least 44×44px. The only exceptions are text links inside a sentence.
- **Phone browser chrome.**
  - `theme-color` follows the active style (generated into `content/theme-canvas.json` by `scripts/themes.mjs`), so luxury gets a dark toolbar.
  - iOS auto-linking of numbers, addresses and emails is off; the real phone numbers are explicit `tel:` links.
  - Form fields set `enterkeyhint` and capitalize names.
- **Focus.** One focus style everywhere: a 3px `accent` outline, offset 3px (`on-band` on dark bands). `scroll-padding` keeps focused and anchored content clear of the sticky header and the mobile bar.
- **Flow pages** (`/go-live`, `/changes`, `/book`, `/unsubscribe`, `/thank-you`):
  - Minimal header (wordmark and phone), no sales nav, noindex.
  - The recommended plan uses the CTA style, and the others use the secondary style.
  - The booking calendar shows 6 days per page with Earlier and Next controls. Day buttons stack two or three across on phones, so nothing scrolls sideways.
- **Admin.**
  - Today, Board and Table views live in `?view=`, and table filters live in the URL so a filtered list can be bookmarked.
  - Board cards can be dragged, or moved with the "Move to…" list on each card (the keyboard and touch path).
  - Destructive actions ask for confirmation.
- **Empty and long content.** Admin lists and board columns have empty states. Long emails and notes wrap (`break-all` / `break-words`), and flex children that hold names use `min-w-0`.

## 6. Copy conventions

- Buttons and button-styled links use **Title Case** (Chicago).
- Headings use **sentence case**, often as a full sentence with a period ("See your design before you pay a cent."). This is a deliberate exception to Title Case headings: it reads as plain speech, which suits the voice in `PRODUCT.md`.
- The business speaks as **"we"** to **"you"**. This is a deliberate exception to "avoid first person": a small local business talking directly is more trustworthy than an anonymous brand.
- Typography details:
  - Curly quotes and apostrophes (’ “ ”) and a real ellipsis (…); "Loading…" and "Sending…" for busy states.
  - Numerals for counts.
  - Prices come from `Intl.NumberFormat` via `formatPrice`, and dates from `Intl.DateTimeFormat` in the visitor's time zone.
- Brand names carry `translate="no"`.
- Copy lives in `content/*.json` and `site.config.json`, not in components. Placeholders use `[TOKEN]` form and are tracked in `TODO.md`.

## 8. Adding things

- **A new style:**
  1. Add it to `content/styles.json` and `scripts/themes.mjs`.
  2. Load its fonts in `app/layout.tsx` with `preload: false`.
  3. Run `node scripts/themes.mjs`.
  4. Check contrast with the a11y suite.
- **A new section:**
  1. Use `Section` with an id and an `h2`, and pull copy from `content/landing.json`.
  2. End it with a `CtaButton` to `/#demo` if it persuades.
  3. Add its anchor to `site.config.json → pages` and to the page map in `app/llms.txt/route.ts`.
- **A blog post:** add a row to the Supabase table `ryzon_landing_blog` (table editor or SQL; `supabase/seed/ryzon_landing_blog_posts.sql` shows the format).
  1. `content` is HTML. Use `<h2>`/`<h3>` for sections; the table of contents and heading ids are built from them, and reading time is computed when left empty.
  2. Set `is_published = true`. `published_at` fills itself the first time.
  3. `/blog`, the post page and the sitemap pick it up within 30 minutes (ISR). Only published rows are readable with the public key.
  4. Optional fields: `featured_image_url` (and its alt), `meta_title`/`meta_description`, `internal_links`, `cta_text`/`cta_href` (defaults to the free demo), `schema_markup` for extra structured data (added next to the generated BlogPosting). An `<h2 id="faq">` section with `<h3>` questions gets FAQPage data automatically.
- **A referrer:** dashboard → Referrers → Add a referrer.
  1. They get a link like `/r/jane-k3p9` and, unless unticked, the `referral_link` email (their link, how it works, a $50 credit per signup, a message to copy).
  2. The link opens the full sales page with "Jane sent you" above the headline. It is noindex, with the home page as canonical.
  3. Leads from it carry `utm_source=referral`, `utm_medium=referrer`, `utm_campaign=<code>`, also when the visitor comes back on their own within 30 days.
  4. Turning a link off sends it to the home page and stops its emails. Credits are tracked by hand: the card shows paid leads and $50 per paid lead.
- **Review requests:** dashboard → Reviews.
  1. Paste names and emails (one per line) and press Send. Anyone asked in the last 30 days is skipped. Every customer also gets a request automatically the moment they pay (`ryzon_landing_review_on_convert`).
  2. The email links to `/review?t=<token>` with one-tap star buttons. The rating only saves when they press Send on the page, so email link scanners can't rate for them.
  3. 4–5 stars: buttons to post on Google (and Facebook or Yelp if set under "Where happy customers post"). Clicks go through `/api/review/go`, which records the platform.
  4. 1–3 stars: "what could we have done better?" and "would you like us to contact you?". Yes puts them under "Unhappy customers to contact" (Reviews and Today) and emails you (`review_contact_admin`). No ends it.
- **Adding existing customers:** dashboard → Add Customer (`/admin/add`). Pick any stage, one person or a pasted list (name, email, phone, business per line). `ryzon_landing_admin_add_customer` inserts the row with no welcome email; automatic emails start paused unless ticked, and a review request goes out only if ticked. An email already in the pipeline is refused.
- **Deleting a person:** their page → Delete this person (or Delete on a Table row). It lists what will go, you type their email, and `ryzon_landing_admin_delete_person` removes every submission with that email (history, change requests, calls, emails and payments cascade), their review requests and any referrer record; the dashboard deletes their uploaded design files first. Stripe, Gmail and anything already sent stay.
- **Scheduling blog posts:** dashboard → Blog. Schedule, Publish Now or Move to Draft. A future `published_at` is hidden by RLS until its time; the blog list catches up within ~30 minutes (ISR). Every 5 minutes pg_cron (`ryzon_landing_blog_go_live`) sends each newly live post once to config `blog_promo_webhook`, the n8n workflow "Ryzon – Blog to Social Kit": kie.ai writes captions and renders 4 graphics (Nano Banana) + 2 vertical videos (Veo 3 Fast), saves them to a new Google Drive folder and emails contact@. Posts live before this existed are `skipped`; use Make Social Content to run one.
- **A new third-party script, font or API:** add its origin to the Content-Security-Policy in `next.config.ts`.
